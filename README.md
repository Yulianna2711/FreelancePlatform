# Лабораторна робота №1

У ході цієї лабораторної роботи було розроблено реляційну базу даних (`freelance_platform`) для платформи фрілансу на базі PostgreSQL та написано бекенд-код на C# (.NET). Зокрема, було реалізовано патерни Repository та Unit of Work для безпечного керування транзакціями через ADO.NET, а також перенесено ключову бізнес-логіку на рівень СУБД за допомогою збережених процедур, тригерів та представлень.

---

##  Технології

- **Мова та платформа:** C#, .NET
- **СУБД:** PostgreSQL 18.6
- **Провайдер доступу до даних:** Npgsql (ADO.NET)
- **Архітектурні патерни:** Repository Pattern, Unit of Work, Factory Pattern

---

##  Структура проєкту

- **`Models`**: Доменні моделі сутностей (`Job`, `Proposal`, `Contract`).
- **`Repositories`**: Інтерфейси та реалізації репозиторіїв (`JobRepository`, `ProposalRepository`, `ContractRepository`), що виконують запити через ADO.NET та викликають збережені процедури.
- **`Services`**: Бізнес-сервіси (`JobService`, `ProposalService`, `ContractService`) з валідацією даних.
- **`UnitOfWork`**: Керування з'єднанням та транзакціями (`IUnitOfWork`, `UnitOfWork`).
- **`Program.cs`**: Головна точка входу з налаштуванням джерела даних та демонстраційними сценаріями.

---

## Архітектурні особливості бази даних

1. **Підтримка Soft Delete (М'яке видалення):**
   - Замість фізичного видалення рядків використовується поле `deleted_at`
   - Для збереження унікальності активних записів реалізовані часткові унікальні індекси (наприклад, `WHERE deleted_at IS NULL`), що дозволяє повторно створювати записи або реєструватися з тим самим email після видалення старого акаунта.
2. **Індексація (Різні типи):**
   - **B-tree індекси** для швидкого пошуку, унікальних обмежень та сортування (наприклад, `idx_contracts_client_start_btree`).
   - **GIN індекс** (`idx_jobs_search_gin`) для ефективного повнотекстового пошуку за назвою та описом вакансій через `to_tsvector`.
3. **Бізнес-логіка на рівні СУБД:**
   - **Збережені процедури** (`create_job`, `submit_proposal`, `create_contract`) інкапсулюють складні перевірки зв'язків та забезпечують транзакційну безпеку.
   - **Розрізи даних (Views)** (`active_jobs_view`, `active_proposals_view`) автоматично фільтрують активні нескасовані записи.
   - **Тригери** автоматично оновлюють поля аудиту `updated_at` та генерують сповіщення (`notifications`) для користувачів.
4. **Обмеження цілісності та зв'язки (Constraints & Foreign Keys):**
   - Використання зовнішніх ключів (`FOREIGN KEY`) із правилами контролю зв'язків між сутностями (`users`, `jobs`, `proposals`, `contracts`), що гарантує реляційну цілісність даних.
   - Обмеження (`CHECK`) для числових полів (наприклад, перевірка, що бюджет вакансії або ціна пропозиції є більшими за нуль).

##  Характеристики програмної реалізації

1. **Контракти (інтерфейси репозиторіїв)**
   - Інтерфейси (`IJobRepository`, `IProposalRepository`, `IContractRepository`) визначають чітку поведінку для отримання активних даних та створення записів.
   - Вищі рівні додатку (сервіси) взаємодіють із даними виключно через ці контракти.

2. **Моделі даних**
   - Класи `Job`, `Proposal` та `Contract` представляють доменні сутності платформи (вакансії, пропозиції та контракти) із відповідними числовими, текстовими та часовими полями.

3. **Отримання активних записів через розрізи даних (Views)**
   - Репозиторії виконують SQL-запити до спеціальних представлень бази даних (`active_jobs_view`, `active_proposals_view`), які на рівні СУБД автоматично фільтрують видалені записи за умовою `deleted_at IS NULL`.

4. **Збережені процедури та Soft-delete**
   - Операції створення записів (`CreateJobAsync`, `SubmitProposalAsync`, `CreateContractAsync`) делегуються збереженим процедурам PostgreSQL (`create_job`, `submit_proposal`, `create_contract`).
   - База даних перевіряє наявність активних пов'язаних профілів та унікальність даних за допомогою часткових індексів із фільтром `deleted_at IS NULL`.

5. **Unit of Work і транзакції**
   - Клас `UnitOfWork` реалізує патерн Unit of Work та інтерфейс `IAsyncDisposable`. Він ініціалізує транзакцію через `_connection.BeginTransactionAsync()` та забезпечує єдиний контекст для репозиторіїв (`Jobs`, `Proposals`, `Contracts`).
   - Сервіси керують життєвим циклом транзакції: викликають `BeginAsync()`, підтверджують зміни через `CommitAsync()` або скасовують їх у блоці `catch` через `RollbackAsync()`.

6. **Інтеграція та фабричний патерн (Factory Pattern)**
   - У файлі `Program.cs` створюється `NpgsqlDataSource` за допомогою `DatabaseConnection.CreateDataSource()`.
   - Використовується фабрика `Func<IUnitOfWork>`, яка дозволяє сервісам створювати нові ізольовані одиниці роботи для виконання операцій.
     
7. **Обробка винятків та безпека транзакцій**
   - Усі операції в сервісах (`JobService`, `ProposalService`, `ContractService`) обгорнуті в блоки `try-catch` з використанням паттерну Unit of Work.
   - У разі виникнення помилки валідації або збою при виконанні запиту до бази даних спрацьовує метод `RollbackAsync()`, що гарантує цілісність даних та запобігає появі "напівзбережених" станів у системі.

## Сценарії використання

1. **Отримання активних вакансій**
   - Сервіс `JobService.GetActiveJobsAsync()` відкриває Unit of Work, викликає `JobRepository.GetActiveJobsAsync()`, яка зчитує дані з `active_jobs_view`, після чого комітить транзакцію.

2. **Створення вакансії**
   - Сервіс `JobService.CreateJobAsync(...)` викликає збережену процедуру `create_job` через репозиторій та повертає числовий ідентифікатор створеної вакансії.

3. **Подання пропозиції та укладання контракту**
   - `ProposalService.SubmitProposalAsync(...)` виконує збережену процедуру `submit_proposal` для додавання відгуку фрилансера на вакансію.
   - `ContractService.HireFreelancerAndCreateContractAsync(...)` перевіряє наявність активної пропозиції та викликає процедуру `create_contract` у межах єдиної транзакції Unit of Work.
